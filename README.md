# MoveGuard

## AI 분석 백엔드 v2 브랜치

`feature/moveguard-pose-analysis-v2`에는 기존 백엔드를 유지하면서 전신 Pose,
손 관절, 선택형 객체 탐지, 관절 각도, RULA 엔진을 분리한 새 분석 API가
포함되어 있습니다. 실행 방법과 API 계약은 `backend/README.md`를 확인하세요.

스마트폰 영상에서 관절 좌표를 추출해 RULA(추후 REBA·OWAS) 기준으로 근골격계 위험도를 자동 채점하고, KOSHA 법정서식(유해요인조사표) 초안을 자동 생성하는 서비스. K-디지털 트레이닝 해커톤(팀 아이디업) 출품작.

이 문서는 **어떤 AI 도구(Claude, ChatGPT 등)를 쓰든 그대로 붙여넣어서 맥락을 공유**할 수 있도록 만든 프로젝트 현황판이다. 작업을 새로 시작하기 전에 이 문서부터 읽는다.

## 이미 확정된 기술적 약속 (기획서 기준)

- 백엔드: **FastAPI + MediaPipe Pose Landmarker**, 채점은 **Python 룰베이스 엔진**
- 저장소: **Firebase (Firestore=이력, Storage=법정서식·사진)**
- 프론트: 기획서 원문은 React였으나, 실제로는 **바닐라 JS로 완성·검증됨** — 계속 바닐라로 갈지, React로 옮길지는 팀 결정 필요 (아래 비교표 참고)
- 하중 입력: **3단계 체크(가벼움/보통/무거움)** — 지금 mvp.html은 kg 숫자입력이라 다름, 맞출지 결정 필요
- 저신뢰 프레임: 조도 자동측정 대신 **관절 인식 신뢰도가 기준치 이하인 프레임은 일괄 제외 + 재촬영 안내** — 아직 미구현
- 개인정보: 원본 영상은 분석 후 **즉시 삭제**, 대표 사진 1장만 보관, 서버엔 관절좌표·위험도 결과만 저장
- 본선 시연: **사전 촬영해 둔 재연 영상을 재생하며 분석 시연** (시뮬레이션임을 고지) — 현장 라이브 촬영 필수 아님
- 일치도 검증 목표: **KOSHA 매뉴얼 수기채점 대비 60%(최소)/70%(목표)**, 테스트 영상 10~15건, 근골격계부담작업 2호 유형, 측면 촬영 좌우 3사이클 이상

## 시간 단축 방법

- **바닐라 JS 유지 (React 포기)** — 이식 시간 10~16시간 절약
- **Firebase 그대로 사용** — 서버리스라 별도 DB 서버 운영·스키마 마이그레이션 부담 없음
- **API 스펙(요청/응답 JSON 형식)을 먼저 문서로 정의** — 백엔드·프론트가 서로 기다리지 않고 병렬 작업 가능
- **Render(또는 배포 대상) 조기 테스트를 제일 먼저 시작** — 의존성 문제를 미리 발견
- **일치도 검증용 영상 촬영을 가장 먼저 착수** — 섭외·촬영은 일정 변수가 크므로 늦어지면 전체 일정이 밀림

## 결정 사항 — DB: Firebase vs 일반 DB

| | Firebase (Firestore + Storage) | 일반 DB (예: Supabase/Postgres) |
|---|---|---|
| 서버 관리 | 서버리스, 별도 DB 서버 운영 불필요 | DB 호스팅 별도 필요 |
| 설정 속도 | 콘솔에서 바로 생성, 빠름 | 스키마 설계 필요 |
| 파일 저장 | Storage로 사진·서식 파일 저장 기본 지원 | 별도 파일 스토리지(S3 등) 필요 |
| 기획서와의 일치 | 이미 명시됨 | 기획서 문구 수정 필요 |
| 팀 학습곡선 | NoSQL — 관계형 DB 경험자는 낯설 수 있음 | SQL 익숙하면 더 편할 수 있음 |

→ 특별한 이유가 없다면 Firebase 유지 추천.

## REBA·OWAS 확장 아키텍처 원칙

REBA·OWAS는 기획서 로드맵상 **본선 이후(10월~) 사업 확장 단계**다. 지금 만들 필요는 없지만, 나중에 지금 짠 코드를 다시 파야 하는 상황을 막으려면 처음부터 이렇게 나눠서 짠다:

- **공유 로직** (평가도구가 바뀌어도 재사용): 영상 업로드·프레임 샘플링, MediaPipe 포즈 추출, 관절 각도 계산 유틸(`angleBetween`, `vec` 등), 위저드 UI 뼈대, 법정서식 렌더링 틀
- **도구별 교체 조각**: RULA/REBA/OWAS 각자의 채점표·기준·Group 구성 — 이것만 새 모듈로 추가

버그를 하나 고칠 때 그게 "공유 로직"에 있으면 REBA/OWAS에도 자동으로 적용된다. "도구별 조각"에 있으면 그 도구에만 적용된다.

**REBA를 기존 MVP에 추가할 때 순서:**
1. 팀공유자료 v4에서 REBA Table A/B/C(또는 별도 REBA 조견표) 확인
2. `moveguard_mvp.html`에서 위 "공유 로직"에 해당하는 부분을 그대로 재사용
3. RULA 전용 채점 함수(`neckScore`, `trunkScore`, `TABLE_A/B/C` 등)를 REBA 버전으로 병렬 추가 (RULA 코드를 지우지 않고, 평가도구 선택에 따라 분기)
4. 실데이터로 검증 → 브라우저 실측 테스트 → 배포, 순서 그대로 반복

## 알아두면 시간 아끼는 것들

- **GitHub 웹/앱은 `.html` 안의 JS를 실행하지 않는다.** 코드만 보여준다. 실제 동작 확인은 로컬 다운로드 후 열거나 GitHub Pages 주소로.
- **`<input capture>` 속성은 모바일 전용이다.** 데스크톱에서 안 보이는 게 정상.
- 이 저장소는 이미 GitHub Pages가 `main` 브랜치 루트로 켜져 있다.
- MediaPipe 관련 배포(Render 등)는 의존성이 무거워서 무료tier 빌드/타임아웃 문제가 잘 남 — 항상 가장 먼저, 빈 뼈대로 조기 테스트할 것.
- Python으로 MediaPipe 쓸 때 최신 Python 버전 호환 여부를 먼저 확인.
